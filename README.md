# Система проката оборудования — КР 1

Консольное приложение Java 17+, PostgreSQL и JDBC. Сохранена предметная область исходного проекта: клиенты, оборудование, заявки на аренду. Интерфейс на русском языке.

## Быстрый запуск на этом компьютере

В папке проекта запустите **run.cmd** двойным щелчком либо выполните в PowerShell:

```powershell
cd C:\Users\нк\RentalSystem
.\compile.ps1
```

В локальном файле `db.properties` уже настроено подключение к отдельной демонстрационной базе `rental_system_demo_20260916`. В ней 5 клиентов, 8 предметов оборудования, 10 заявок и все 5 статусов. Исходная база `rental_system` не изменялась. Демо-данные добавляются SQL-скриптом один раз, а не при каждом запуске приложения.

## Установка на другом компьютере

1. Установите JDK 17 или новее и PostgreSQL. Для Maven-сборки нужен Maven 3.
2. Создайте **новую пустую базу**. Например, из SQL Shell (psql) под пользователем PostgreSQL:

```sql
CREATE DATABASE rental_system;
```

3. Из папки проекта выполните:

```powershell
psql -X -v ON_ERROR_STOP=1 -U postgres -d rental_system -f database.sql
Copy-Item db.properties.example db.properties
notepad db.properties
```

Если psql отсутствует в PATH, используйте его полный путь, например:
`& 'C:\Program Files\PostgreSQL\18\bin\psql.exe' ...`.

Впишите пароль своего PostgreSQL в `db.properties`. Этот файл не включён в переносимый архив и исключён из Git. Приоритет настроек: Java `-Ddb.url/-Ddb.user/-Ddb.password`, затем переменные `DB_URL/DB_USER/DB_PASSWORD`, затем файл. Путь к другому файлу можно задать через `-Ddb.config=...`.

4. Запустите `run.cmd`. Скрипт компилирует исходники с библиотеками из `lib`; интернет и Maven для него не нужны. Если PostgreSQL не запущен или пароль неверен, меню покажет понятную ошибку и позволит продолжить.

**database.sql предназначен для новой базы.** Скрипт выполняется транзакционно и не заменяет существующие таблицы. Для старой базы используйте отдельную новую БД; этот скрипт не является миграцией её данных.

## Maven

```powershell
mvn package
java -Dfile.encoding=UTF-8 -cp "target/classes;lib/*" ru.mirea.project.Main
```

JAR в `target` содержит приложение; зависимости остаются внешними. Можно запустить:
`java -cp "target/rental-system-1.0-SNAPSHOT.jar;lib/*" ru.mirea.project.Main`.

## Меню

1. Клиенты — создание, просмотр, поиск по ID, изменение, удаление.
2. Оборудование — CRUD и сортировка по цене.
3. Заявки — CRUD, изменение статуса, сортировка по дате/стоимости в обе стороны.
4. Поиск — клиенты, оборудование, общий поиск заявок, отдельно по клиенту и по оборудованию.
5. Фильтры — категория/доступность оборудования, статус/дата начала заявки.
6. Статистика — количество заявок, завершённых/активных/отменённых, выручка завершённых аренд, клиенты, оборудование, доступные/занятые предметы.
7. Экспорт — отдельные Excel и CSV для всех трёх сущностей, в папку `exports`.
8. Просмотр содержимого таблиц.
0. Возврат или выход.

В меню статусов номера идут от 0 до 4; это выбор enum, а не команда «Назад». Даты вводятся как `2026-09-16`, суммы — через точку. Неверный ввод возвращает в соответствующее меню. Конец входного потока завершает программу без зацикливания.

## Правила аренды

- Обязательны ФИО, телефон (не менее 5 цифр), корректный уникальный email, название и категория оборудования.
- Цена и итоговая стоимость положительны, не более 9999999999.99, максимум два знака после точки.
- Клиент и оборудование должны существовать.
- Новая дата начала не раньше сегодняшней, окончание строго позже начала.
- Период считается как `[начало, окончание)`: с 16-го до 17-го — один оплачиваемый день. Однодневная аренда требует следующей даты окончания.
- Стоимость вычисляет сервис: цена за день × число дней. Изменение поля стоимости вызывающим кодом не позволяет подменить расчёт.
- Один предмет закрепляется за одной незакрытой заявкой, даже если её даты в будущем. Календарное бронирование нескольких непересекающихся периодов в КР 1 не реализовано.
- `CREATED → ACTIVE → COMPLETED`; также `CREATED → CANCELLED` и `ACTIVE → OVERDUE → COMPLETED`. Из конечных состояний переходов нет.
- Выдать предмет можно не раньше начала аренды. Просрочку можно установить только после даты окончания; она отмечается вручную в меню статусов.
- Менять даты можно только у `CREATED`. Смена клиента, предмета или статуса через обычное редактирование запрещена.
- Удаление `ACTIVE/OVERDUE` запрещено до возврата. Удаление созданной заявки и её отмена освобождают оборудование.
- Нельзя вручную сделать оборудование доступным, если существует незакрытая заявка.
- Клиента/оборудование со связанными заявками удалить нельзя. FK использует RESTRICT, история не удаляется каскадно.
- Заявка и доступность оборудования сохраняются одной транзакцией. Блокировка строки оборудования и уникальный частичный индекс защищают от двух одновременных бронирований.

## Структура

```text
Main → view/Menu → service/* → repository/* → JDBC → PostgreSQL
                   ↓
              util/DatabaseConnection (транзакции)
              util/DataExporter (Excel, CSV)
```

`model` содержит классы с закрытыми полями, конструкторами и методами, а также enum.
`Repository<T, ID>` — общий интерфейс CRUD. `ClientService` обращается к реализации через интерфейс.
`JdbcRepository<T>` переиспользует параметризованные запросы и закрытие JDBC-ресурсов.
`service` содержит бизнес-проверки; SQL в меню отсутствует.
Сортировки, поиск клиентов, категории и расчёт выручки показывают Collections/Stream API.
Собственные исключения: `BusinessException`, `EntityNotFoundException`, `DataAccessException`.

## Проверки

```powershell
.\verify.ps1
```

Набор `RegressionChecks` содержит 73 проверки, использует настоящий PostgreSQL и создаёт уникальную временную схему `rental_verify_...`. У пользователя БД должно быть право CREATE SCHEMA. В конце удаляется только созданная тестовая схема; рабочие таблицы не затрагиваются. При аварийном завершении процесса схема может остаться.

Проверяются CRUD, бизнес-правила, откат при ошибке второй записи, конкурентная бронь из двух потоков, ограничения FK/UNIQUE, поиск/фильтры/сортировки, Excel/CSV, ввод и потеря соединения.
Это отдельный исполняемый набор, **mvn test сам его не запускает**. Команда `mvn package` проверяет сборку, `verify.ps1` — поведение приложения.


- `exports/*.xlsx` — фактическая выгрузка из PostgreSQL (создаётся через меню).
